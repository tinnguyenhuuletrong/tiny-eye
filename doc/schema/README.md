# doc/schema — generated grammars

Everything here except this README is generated by `make schemas` from the sources of truth,
and `cargo test` (tests/schemas.rs) fails when a file is stale. Never edit these files by hand.

| File | What | Source of truth |
| --- | --- | --- |
| `tqs.schema.json` | JSON Schema of a TQS 3 query document | `TqsDocument` in `api/openapi.yaml` |
| `dashboard.schema.json` | JSON Schema of a dashboard YAML file (`dashboards/*.yaml`) | `Dashboard` / `Panel` in `api/openapi.yaml` |
| `config.schema.json` | JSON Schema of the config file, with every default and description | config structs (`crates/engine/src/config.rs`) + `config/default.yaml` |
| `mcp-tools.json` | the exact MCP `tools/list` result: names, descriptions, input schemas | `x-mcp-tool` on operations in `api/openapi.yaml` |
| `mcp-tools.md` | the same, as a table | same |
| `tqs-formula.tmLanguage.json` | TextMate grammar for formula expressions (`100 * e / greatest(a, 1)`) | `tqs::formula::FUNCS` |

## Editors

- **VS Code**: `.vscode/settings.json` maps the schemas (Red Hat YAML extension for YAML, built-in
  for JSON); the YAML files also carry a `# yaml-language-server: $schema=…` header. You get
  validation, completion and hover docs (defaults included) for config, dashboards and TQS.
- **Monaco** (our dashboard UI): register `tqs.schema.json` with `monaco.languages.json.jsonDefaults.setDiagnosticsOptions({ schemas: [...] })`
  for the JSON editor, or `monaco-yaml` with `dashboard.schema.json` for YAML panels. Formula
  fields can use `tqs-formula.tmLanguage.json` through `monaco-textmate`, or a Monarch tokenizer
  built from the same function list.
- A VS Code extension later needs only `contributes.jsonValidation` / `contributes.grammars`
  pointing at these files.

The authoritative validation is still the engine (`POST /api/v1/validate`): it reports every problem
with a code and JSON path, including cross-field rules a JSON Schema cannot express.
