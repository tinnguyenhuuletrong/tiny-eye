`schema/generated/` holds machine-readable grammars for TQS documents, dashboards, the configuration file, MCP tools and formula expressions. Editors use them for completion, hover documentation and validation while you type, and agents can read them to learn the query language.

All files are generated by `make schemas` from the sources of truth. Do not edit them by hand.

## What `schema/generated` contains

| File | Describes | Generated from |
| :--- | :--- | :--- |
| `tqs.schema.json` | A TQS 3 query document | `TqsDocument` in `api/openapi.yaml` |
| `dashboard.schema.json` | A dashboard YAML file (panels with `query` and `ui`) | `Dashboard` in `api/openapi.yaml` |
| `config.schema.json` | The configuration file; every key with its description and default, none required | the config structs in `crates/engine/src/config.rs` and `config/default.yaml` |
| `mcp-tools.json` | The exact MCP `tools/list` result: name, description and input schema of each tool | operations with `x-mcp-tool` in `api/openapi.yaml` |
| `tqs-formula.tmLanguage.json` | TextMate grammar for formula expressions (`expr` in `formulas`) | the formula function list `tqs::formula::FUNCS` |

`make schemas` also writes [MCP tools](mcp-tools.md) (`docs/reference/mcp-tools.md`).

The JSON Schemas use draft 2020-12, are self-contained (every reference is inlined under `$defs`), and have an `$id` under `https://tiny-eye.local/schema/`, for example `https://tiny-eye.local/schema/tqs.schema.json`. That host is an identifier, not a server; point editors at the local files.

The formula grammar (scope name `source.tqs-formula`) marks function names (`abs`, `round`, `least`, `greatest`, `clamp`, `coalesce`) followed by `(`, the variable `time`, numbers, query names, arithmetic operators and punctuation, and flags any other character as invalid.

:::note
The JSON Schema checks shape: fields, types, enums, patterns and simple ranges. Cross-field rules (a window required for `rate`, formula references, grouping compatibility and so on) are checked only by the engine. Run `POST /api/v1/validate` for the full verdict; see the [TQS reference](../deep-dive/tqs-reference.md#problem-codes).
:::

## VS Code

Install the YAML extension (Red Hat, based on yaml-language-server). JSON support is built in.

### Workspace settings

The repository ships `.vscode/settings.json`:

```json
{
  "yaml.schemas": {
    "schema/generated/config.schema.json": ["config/*.yaml"],
    "schema/generated/dashboard.schema.json": ["dashboards/*.yaml"]
  },
  "json.schemas": [
    { "fileMatch": ["api/examples/*.json"], "url": "./schema/generated/tqs.schema.json" }
  ]
}
```

Add patterns for your own locations, for example `"schema/generated/dashboard.schema.json": ["dashboards/*.yaml", "examples/*/dashboards/*.yaml"]`, or a `fileMatch` for directories where you keep TQS JSON files.

### Per-file headers

A first-line comment binds one YAML file to a schema, with a path relative to the file:

```yaml
# yaml-language-server: $schema=../schema/generated/config.schema.json
```

```yaml
# yaml-language-server: $schema=../schema/generated/dashboard.schema.json
id: shop
title: Shop overview
panels: []
```

`config/default.yaml`, `config/dev.yaml` and `dashboards/self.yaml` carry such headers. Dashboards saved from the UI get the header `# yaml-language-server: $schema=https://tiny-eye.local/schema/dashboard.schema.json`; since that URL does not resolve, keep a `yaml.schemas` mapping (as above) for the dashboards directory.

For a JSON TQS file, add `"$schema"` only if your tooling strips it before sending: the engine refuses unknown fields, so a document with `"$schema"` is rejected by `POST /api/v1/query`. Prefer a `json.schemas` mapping.

### Formula highlighting

`tqs-formula.tmLanguage.json` can be registered by a small VS Code extension (`contributes.grammars` with `scopeName: source.tqs-formula`) or injected into JSON and YAML strings. tiny-eye does not ship that extension.

## Monaco

Monaco's JSON language service accepts the TQS schema directly:

```ts
import * as monaco from "monaco-editor";
import tqsSchema from "../schema/generated/tqs.schema.json";

monaco.languages.json.jsonDefaults.setDiagnosticsOptions({
  validate: true,
  schemas: [{ uri: tqsSchema.$id, fileMatch: ["*.tqs.json"], schema: tqsSchema }],
});

const model = monaco.editor.createModel(
  JSON.stringify({ tqs: "3", id: "explore", kind: "timeseries", time: { from: "-1h" }, queries: [] }, null, 2),
  "json",
  monaco.Uri.parse("inmemory://explore.tqs.json"),
);
monaco.editor.create(document.getElementById("editor")!, { model });
```

Use the dashboard schema the same way for dashboard JSON. The formula grammar works in Monaco through a TextMate bridge such as monaco-textmate. The web UI plans to use Monaco with this schema for its Explore TQS editor (see [Dashboards and the web UI](../deep-dive/dashboards-and-ui.md)).

## Regenerate

```bash
make schemas     # cargo run --bin tiny-eye -- schemas --root .
```

It prints each file it wrote. Commit the result with the change that caused it. Run it after changing:

- a TQS or dashboard schema, or an `x-mcp-tool`, in `api/openapi.yaml`;
- a config struct or its doc comments in `crates/engine/src/config.rs`, or a default in `config/default.yaml`;
- the formula function list in `crates/tqs/src/formula.rs`.

## The golden test

`crates/server/tests/schemas.rs` keeps the files honest, and runs in `make test` (and therefore in CI):

- `doc_schema_is_up_to_date` generates every file in memory and compares it with the committed copy. Any difference fails with `stale generated files: [...] — run make schemas and commit`.
- `config_files_match_the_config_schema` validates `config/default.yaml` and `config/dev.yaml` against the config schema and checks that a typo (`flush_intervall`) is refused.
- `dashboards_match_the_dashboard_schema` validates every file in `dashboards/`.

`crates/server/tests/openapi.rs` additionally checks that the TQS schema and the engine's validator accept every example in `api/examples/` and refuse the same shape errors. See [API and code generation](../deep-dive/api-and-codegen.md).
